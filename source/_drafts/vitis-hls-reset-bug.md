---
title: A Missing Reset in RTL Generated by AMD Vitis HLS 2025.1
date: 2026-11-18
---

I work on formally verifying the RTL that high-level synthesis generates from C.
While checking a small design, I found that the RTL generated by AMD Vitis HLS 2025.1 can assert `ap_done` right after reset, before performing any array write.

The C source is a loop over `N = 1024` elements computing `a[i] += b[i]*b[i] + c[i]*c[i]`.
With inputs `A = 0`, `B = 1` and `C = 2`, every element `A[k]` must equal 5 at completion.
I generated the RTL with these settings:

- Vitis HLS 2025.1 with the Vivado IP flow
- Default reset configuration, with no `config_rtl` override
- Clock constraint of 4 ns
- Automatic loop pipelining (II = 2, depth 12)

AMD's documentation states that the default control reset covers control registers used in state machines and I/O protocol generation.
In the generated RTL, two loop-exit control registers have no reset branch and no initial value.
One of those registers feeds the completion condition directly, without being qualified by the pipeline-valid signal.

The circuit therefore behaves differently depending on the values those two registers hold when reset is released.
If the registers hold 1, the design reports done at cycle 1 with all outputs still 0.
If the registers hold 0, the design finishes correctly at cycle 2057 with every output equal to 5.
It is the same RTL, the same reset sequence and the same start handshake.

I found the bug with a bounded model check in SymbiYosys of this assertion:

```systemverilog
assert (!ap_done || saw_write);
```

The check fails at step 4, because the solver picks the unspecified initial values of those registers.
I then reproduced the failure in simulation with AMD's own Vivado Simulator (XSim) and with Icarus Verilog.

Adding `config_rtl -reset all` gives every register a reset and makes the failure disappear, at the cost of resetting the datapath too, which adds area and reset fanout.
I reported the bug to AMD. AMD confirmed it and will fix it in the next release.

Simulation that starts every register at 0 hides this bug. A formal tool that leaves unspecified registers free finds it in seconds.
A public reproducer with the C source, the unmodified generated RTL, the testbench and the formal check is at [github.com/lichye/vitis-hls-reset-repro](https://github.com/lichye/vitis-hls-reset-repro).
